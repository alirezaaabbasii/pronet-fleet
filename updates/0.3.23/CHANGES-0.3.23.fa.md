# Pronet Fleet 0.3.23

- در منوی ایران گزینهٔ **۸) Remove a tunnel** و در منوی خارج گزینهٔ **۴) Remove a tunnel** اضافه شد. فهرست تونل‌ها با نام، وضعیت، آدرس کاربر و شناسه نمایش داده می‌شود؛ پس از انتخاب و تأیید، فقط همان تونل برای پاک‌سازی از هر دو سرور درخواست می‌شود.
- برنامه، موتورهای مشترک، ثبت سرورها، تنظیمات پنل و بقیهٔ تونل‌ها باقی می‌مانند. تونل‌های خطاخورده که قبلاً پاک‌سازی‌شان تأیید شده، در فهرست حذف نمایش داده نمی‌شوند. تلاش منتظر اتصال نیز قابل لغو است.
- پیام موفقیت فقط پس از دریافت وضعیت STOPPED نشان داده می‌شود. اگر یک سرور در دسترس نباشد یا توقف سرویس‌ها تأیید نشود، وضعیت نامطمئن یا در انتظار نمایش داده می‌شود. برای تکرار درخواست، پس از برگشت سرور دوباره همین گزینه را انتخاب کنید.
- خروج با Ctrl+C از صفحهٔ انتظار، درخواست حذفِ ثبت‌شده را لغو نمی‌کند؛ پیام این حالت مشخص شده است. فقط فایل فرمان اتصالِ همان تونل، بعد از تأیید حذف پاک می‌شود؛ فرمان منتظر تونل دیگری باقی می‌ماند.
- فرمان قدیمی `sudo pronet remove TUNNEL_ID` حفظ شده و مثل قبل درخواست پس‌زمینه می‌فرستد. گزینهٔ منو منتظر تأیید می‌ماند. ارتباط با هماهنگ‌کننده برای حذف دوطرفه لازم است؛ در نبود آن، موفقیت اعلام نمی‌شود.
- خطای اتصال اولیهٔ خارج به ایران اکنون بین «شکست اتصال TCP» و «وصل‌شدن TCP ولی کامل‌نشدن TLS» تفاوت می‌گذارد. بررسی اثر انگشت گواهی و محدودیت‌های TLS تغییر نکرده‌اند. واضح‌ترشدن پیام، به معنی رفع اختلال شبکه یا فایروال سرور نیست.

برای خطای TLS، روی ایران فعال‌بودن `pronetf-hub.service` و گوش‌دادن روی پورت چاپ‌شده در فرمان خارج را بررسی کنید. IP و پورت باید مربوط به همین هماهنگ‌کننده باشند؛ فایروال سیستم و دیتاسنتر و اختلال مسیر نیز باید بررسی شوند. خودِ این خطا، خرابی موتور تونل یا شکست دانلود از GitHub را ثابت نمی‌کند.
