# Pronet Fleet 0.3.21

- نصب ایران پیش از نصب پیش‌نیازها، دربارهٔ تست میرور سؤال می‌کند. در صورت انتخاب، چند میرور هم‌زمان بررسی می‌شوند. فراداده باید امضای معتبر اوبونتو و نام انتشار درست داشته باشد. از میان گزینه‌های پاسخ‌گو، همهٔ گزینه‌های پاسخ‌گو برای دریافت کامل فهرست‌ها و بسته‌های لازم امتحان می‌شوند؛ خطای 403 باعث امتحان گزینهٔ بعد می‌شود.
- میرور فقط در یک محیط موقت APT استفاده می‌شود. فایل‌های اصلی APT تغییر نمی‌کنند؛ محیط موقت پس از نصب پیش‌نیازها یا خروج با خطا پاک می‌شود. انتخاب بر اساس اندازه‌گیری همان سرور است. سرعت درج‌شده مربوط به فایل InRelease است، نه تضمین سرعت همهٔ بسته‌ها.
- DNS فعلی خوانده می‌شود و همراه چند DNS عمومی با شش پرس‌وجوی کوچک به ازای هر DNS بررسی می‌شود. تنها گزینه‌هایی که همهٔ پرس‌وجوها را جواب دهند پیشنهاد می‌شوند. تنظیمات DNS، Netplan و systemd-resolved هرگز تغییر نمی‌کنند. زمان DNS، معیار پینگ بازی یا ظرفیت دانلود نیست.
- Ubuntu 22.04 با sources.list و نسخه‌های جدید با قالب DEB822 پشتیبانی می‌شوند. نام انتشار از خود سیستم خوانده می‌شود. معماری arm64 فقط مخزن مناسب Ubuntu Ports را آزمایش می‌کند.
- فرمان خارج همان get.sh اصلی GitHub است؛ تست میرور و DNS ایران در فرمان join اجرا نمی‌شود.
- فرمان‌های جفت‌سازی جدید مهلت زمانی ندارند. کد ۱۲۸ بیتی تصادفی، یک‌بارمصرف است. لغو تونل منتظر از طریق stop، فرمان را باطل می‌کند. کدهای چهاررقمی قدیمی مهلت قبلی خود را حفظ می‌کنند؛ برای فرمان بدون انقضا، جفت‌سازی جدید بسازید.
- در نصب تعاملی، پس از تست اولیه می‌توانید انتخاب خودکار یا دستی داشته باشید. در حالت دستی، ابتدا اصلی و سپس تا دو پشتیبان انتخاب می‌شوند؛ تکرار ممکن نیست. در سرور با RAM کم، سقف همان یک پشتیبان باقی می‌ماند. همهٔ انتخاب‌ها همچنان باید تست طولانی و بررسی سرویس دائمی را قبول شوند. اگر تست نهایی یک انتخاب دستی شکست بخورد، نصب با توضیح متوقف و پاک‌سازی می‌شود.
- برای ادامهٔ انتخاب پس از بستن صفحه، روی ایران `sudo pronet watch` بزنید. پیش از انتظار، سرویس‌های آزمایشی بازنشسته می‌شوند تا زمان اعتبار آن‌ها وسط تست نهایی تمام نشود. انتظار انتخاب حداکثر ۲۰ دقیقه است؛ بدون پاسخ، نصب پاک‌سازی و متوقف می‌شود. این محدودیت مربوط به مرحلهٔ انتخاب حامل است، نه فرمان جفت‌سازی خارج.
- اجرای بدون ترمینال و `pair --no-wait` همچنان خودکار است. بازیابی خودکار منتظر انتخاب کاربر نمی‌ماند.
- Gaming دیگر حالت balanced را به thorough تبدیل نمی‌کند. balanced دو دور طولانی و thorough سه دور دارد. تست تلفات، پینگ و جیتر در حالت عادی و زیر بار و بررسی پس از نصب دائمی حفظ شده‌اند.

نصب یا آپدیت (روی هر دو سرور برای ساخت تونل جدید):

```bash
curl -fsSL https://raw.githubusercontent.com/alirezaaabbasii/pronet-fleet/main/get.sh | sudo bash
```

آپدیت تنظیمات تونل‌های موجود را تغییر نمی‌دهد. سرویس‌های مدیریت نسخهٔ جدید را می‌گیرند؛ موتور و gateway تونل‌های فعال همان سرویس‌های موجود می‌مانند.
