# Pronet Fleet 0.3.6

نسخهٔ اصلاح سیاست بازیابی و حافظهٔ واسط عبور داده. تغییرات در [CHANGES-0.3.6.fa.md](CHANGES-0.3.6.fa.md) و [CHANGES-0.3.4.fa.md](CHANGES-0.3.4.fa.md) آمده‌اند.

حالت پیش‌فرض stable همان مسیر اصلی و پشتیبانِ انتخاب‌شده را نگه می‌دارد؛ خرابی هم‌زمان باعث اجرای بی‌پایان آزمایش روش‌های تازه نمی‌شود. پاسخ echo، تأیید ورود کاربر یا سرعت برنامه نیست.

آزمون محلی: ۱۳۷ تست موفق؛ Linux: ۱۳۷ تست موفق. نتیجه و محدودهٔ تأیید زنده در STABILITY-VALIDATION.json آمده است. گزارش‌های WAN قدیمی داخل بسته، مربوط به نسخه‌های پیشین‌اند.

ارتقای مدیریت، موتورهای زنده را restart نمی‌کند. برای اعمال اصلاح حافظه روی اتصال‌های موجود باید واسط داده در زمان مناسب یک‌بار مجدداً شروع شود؛ جزئیات در یادداشت 0.3.6 است.

## Quick start (0.3.6)

**Iran server**
```sh
curl -fsSL https://raw.githubusercontent.com/alirezaaabbasii/pronet-fleet/main/get.sh | sudo bash
```
Choose `1`, press Enter for the detected public IP and for client port 2053. The Iran server prints ONE command.

**Foreign server**: paste that command, for example
```sh
curl -fsSL https://raw.githubusercontent.com/alirezaaabbasii/pronet-fleet/main/get.sh | sudo bash -s -- join PNF1-...
```
The Iran screen shows live progress and a final report. Then create the panel inbound on the foreign server
(listen 0.0.0.0, same port) and give clients `IRAN_IP:PORT`. Details: [CHANGES-0.2.5.md](CHANGES-0.2.5.md).

## شروع

[راهنمای نصب و عملیات فارسی](OPERATOR.fa.md) · [پشتیبانی و نتیجهٔ آزمون‌ها](SUPPORT.md) · [گزارش آزمون محلی](unit-test-report.txt)

```sh
sudo sh install.sh
sudo pronet
```

این دستورها را داخل پوشهٔ بازشدهٔ بسته اجرا کن. پیش‌نیاز: Linux با systemd، Python 3.10+ و معماری amd64 یا arm64.
نصب بسته فقط فایل‌های برنامه را کپی می‌کند. ساخت مرکز، ثبت سرور و ایجاد تونل از طریق منو یا فرمان‌ها انجام می‌شود.
در نصب تازه، منوی ایران مرکز HTTPS را روی همان سرور راه‌اندازی می‌کند و فرمان ثبت سرور خارج را می‌دهد.
ثبت اولیهٔ هر دو سرور به فایل محرمانهٔ bootstrap همان مرکز نیاز دارد؛ سپس جفت‌سازی با کد چهاررقمی پنج‌دقیقه‌ای انجام می‌شود.

## قابلیت‌های پیاده‌شده

- نقش ایران/خارج، کد یک‌بارمصرف، عامل‌های خروجی HTTPS و صف عملیات با هویت مستقل هر سرور.
- ۲۱ پروفایل از پنج موتور BackPack، FRP، Chisel، Rathole و Wstunnel؛ ۲۰ نامزد پیش‌فرض و XDI آزمایشی به‌صورت اختیاری.
- سنجش واقعی تأخیر، انتقال دوطرفه، صحت بایت‌ها، نیم‌بستن اتصال و ادامهٔ اتصال بعد از بیکاری؛ انتخاب خودکار مسیر اصلی و حداکثر یک پشتیبان گرم.
- سه شدت سنجش quick/balanced/thorough؛ حالت thorough سه تأیید پیاپی برای نامزد منتخب دارد.
- ارتقای آفلاین نسخهٔ مدیریت با backup و rollback؛ باینری موتور فعال تا سنجش تازه ثابت می‌ماند.
- نصب دائمی systemd، بازیابی محدود، تعویض مسیر برای اتصال‌های جدید و تلاش مجدد محدود بین روش‌های قبلاً موفق.
- Host عمومی TCP روی IP انتخابی ایران و پورت 2053؛ پورت‌های حمل مستقل. جریان TLS/WS/XHTTP کاربر بدون خاتمه‌دادن TLS منتقل می‌شود.
- چند IP ایران و چند خارج، تشخیص اشغال سوکت و NAT، کنترل تداخل SSH/زیرشبکه‌ها، نگهداری مالکیت دقیق منابع.
- داشبورد HTTPS فقط‌خواندنی و مانیتور ترمینال؛ سلامت واقعی تونل، وضعیت اینباند، منابع، ترافیک و IP تخصیص‌نیافته/بیکار/نامشخص.
- موتورهای Linux هر دو معماری داخل بسته‌اند؛ SHA256 از دارایی‌های نسخهٔ رسمی ثبت شده و پیش از استخراج کنترل می‌شود.

این‌ها قابلیت‌های کد هستند؛ جدول [SUPPORT.md](SUPPORT.md) مشخص می‌کند کدام بخش واقعاً روی چه محیطی آزموده شده است.
۲۶ گزینهٔ گزارش تحقیق همگی آداپتور اجرایی ندارند. «سریع‌ترین نتیجهٔ کوتاه‌مدت» تضمین پایداری چندروزه یا عبور از فیلترینگ نیست.

## ساختار

`pronet/` کد برنامه؛ `tests/` آزمون‌های واحد، شبکه و سناریوی Linux؛ `vendor/` فایل‌های رسمی قفل‌شده؛
`assets.lock.json` نسخه‌ها و هش‌ها؛ `sources/` منبع برچسب‌خوردهٔ BackPack؛ `licenses/` مجوزهای اصلی؛
`SHA256-MANIFEST.json` هش فایل‌های بسته. فایل هش برای کشف خرابی است و امضای ناشر محسوب نمی‌شود.

[مرور پژوهشی تونل‌ها](TUNNELS.fa.md) و [فهرست ماشینی تحقیق](engine-catalog.json) وضعیت تحقیق را جدا از قابلیت اجرایی نگه می‌دارند.
[DESIGN.md](DESIGN.md) سند طراحی و معیارهای هدف است؛ مرجع امکانات نسخهٔ فعلی همین README، SUPPORT و راهنمای عملیات است.
